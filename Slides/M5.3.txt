     Updated on every operation.
      Used to replay recent changes.
    
    image - old backup , journal - recent changes

6. backup node 
     BackupNode = a read-only NameNode that keeps an up-to-date image in memory and creates checkpoints faster than CheckpointNode.

//HDFS Architecture 
  HDFS uses master–slave architecture.
  NameNode = master → manages metadata, namespace, and file operations (open/close/rename).
  DataNodes = slaves → store actual data blocks.
  files are split into blocks (default 64 MB) and stored on multiple DataNodes.
  NameNode decides which block goes to which DataNode.
  DataNodes handle read/write, and perform block creation, deletion, and replication when told by NameNode.
  Works on top of existing file system.
  Data is stored as blocks.
  Reliability is achieved using replication.
  NameNode stores all metadata.
  No caching because files are typically very large.

 2. namenode : if this fails then entire file system stops because it has all the metadata  to handle this 
 persistent backup : copy of namenodes metadata(fsimage +edits) is saved on to disk

//replication policy 
 rule 1: single DataNode cannot store two copies of the same block.
   -> This protects data if that DataNode fails
 rule 2: A single rack cannot have more than two replicas of the same block (if enough racks exist).
   -> → This protects data even if a whole rack goes down.


//introduction to MapReduce
  Why MapReduce?

• Traditional Enterprise Systems normally have a centralized
server to store and process data.
•  the centralized system creates too much of a
bottleneck while processing multiple files simultaneously.

• Google solved this bottleneck issue using an algorithm called
MapReduce.
• MapReduce divides a task into small parts and assigns them to
many computers.
• Later, the results are collected at one place and integrated to
form the result dataset.

How MapReduce Works?

• MapReduce is a software framework to process large datasets across multiple machines. 
Map data into multiple <key, value> pairs –
 Reduce over all pairs with the same key.
• Consider a simple example of finding the count of every word
present in a document.

 HDFS Basics

HDFS uses master/slave architecture.
NameNode = master, DataNodes = slaves.
Files are stored as blocks (default 64 MB).
HDFS provides fault tolerance and high throughput.
HDFS runs on commodity hardware.
HDFS works on write-once, read-many model.
Computation moves to data, not the other way.
HDFS avoids caching because files are very large.

NameNode
Stores metadata (file names, block locations).
Keeps namespace in memory for fast access.
Only one NameNode per cluster.
Performs open, close, rename operations.
Uses checkpoint + journal for persistence.

DataNode
Stores actual data blocks.
Sends heartbeats every 3 seconds.
Sends block reports (block ID, size, generation).
Replication, deletion, creation done on NN instruction.
If heartbeat missing for 10 mins → DataNode is dead.

CheckpointNode
Downloads checkpoint + journal
Merges them
Creates a new checkpoint
Helps reduce NameNode restart time

BackupNode
Maintains in-memory updated image.
Can create checkpoint without downloading.

Failure & Recovery
NN tracks DN via heartbeats.
If DN fails → lost blocks are replicated elsewhere.
NN failure = file system failure.
Recovery options: backup + checkpointing.

Replication Policy
Rule 1: One DN cannot store more than one replica.
Rule 2: One rack cannot store more than two replicas.

Why Hadoop?
Needed for large datasets.
Hardware failures are common.
Must be efficient, reliable, open-source.

Why MapReduce?
Centralized systems = bottleneck.
Google solved using MapReduce.
Divides tasks → runs in parallel → combines results.

MapReduce Working
Map: converts data to (key, value) pairs.
Reduce: groups by key and aggregates values.

When NameNode writes metadata changes to the journal, it must flush (write to disk) and sync (force it to stable storage).
