
//Cloud security 

 cloud security is security measures applied to protect data, applications and infrastructure within the cloud computing technology 
  these meaures are configured to protect data , support regulatory compliance, and protect customers privacy  as well as setting authentication rules 
   
   from authenticating access to filtering traffic 
    it ensures data stored in the cloud is

     purpose of cloud security 
      protect cloud data, support regulatory compliance , protect user privacy, control Access

Authentication : is the process of verifying who a user  is 
  operating system usually authenticates user using 
  1. what you know ? - username/password 
  2. what you have ? - card/key 
  3. what you possess ? - user attribute - fingerprint/eye retina 

OTP - it is password that si valid for only once , for a single login session or transaction 
generated using 
 1. random numbers 
 2. secret keys 
 3. network passwords 

 Advantages of otp over static password 
  | **Advantage**                                   | **Explanation**                                                        |
| ----------------------------------------------- | ---------------------------------------------------------------------- |
| **1. Prevents reuse attacks**                   | OTP works only once; cannot be reused even if stolen.                  |
| **2. Protects against password theft**          | Even if a hacker gets your OTP, it becomes useless after one attempt.  |
| **3. Not vulnerable to replay attacks**         | Old OTPs cannot be used again.                                         |
| **4. Reduces risk of brute-force attacks**      | Valid only for a few seconds/minutes.                                  |
| **5. No need to remember**                      | OTP is generated automatically; users don’t have to memorize anything. |
| **6. Works as two-factor authentication (2FA)** | It adds an extra layer of security along with a password.              |


Replay Attack 
  A replay attack is a type of cyberattack where an attacke rcaptures the valid data transmission(like a login request or assword) and re-sends(re-plays) it later to trick the system 
       Replay Attack = attacker records your login message and replays it to get in again.
    
    The attacker does NOT need to know your password.They just replay the already-used message.

 //how a replay attack works 
  1. you login by sending :
      username + password -> server 
  2. attacker quietly records this message.
  3. later the attacker sends the same captured message to the server 
  4. server thinks it is you -> attacker gets access 
  
  No need to crack the password — only replay the old packet.

  why otp is not vulnerabel to replay attack 
  because :
   otp works only once 
   once used , it immediately becomes invalid 
   replaying the same otp again - server rejects it 
   otp expires in seconds/minutes 
   so attacker cannot reuse or replay hte same otp

//security 
  CIA triad 
  C- Confidentiality 
     - only authorized people can access the data 
     - protecting data from unauthorized access 
  ex: password, encryption , otp 
  I - Integrity 
    - data must remain correct, unchanged and trustworthy

// top cloud security risks 
  1. loss of governance 
      when you use cloud , you loose some control because the cloud provider manages 
       hardware, updates, security policies , backup systems 
    so you have to trust them 
    if sla doesnt guarantee security -> risky 
    because if in oru laptop we control everything but in cloud the provider controls everything 
  2. Lock in 
      it becomes hard to move from one cloud provicer to another because 
      . different data formats , different apis , nost standard migration tools 
    ex: if all your apps are built only in aws , you cannot easily shift to azure 
    this creates dependency -> you got locked into one provider 

  3. isolation failure : Cloud uses multi-tenancy (many customers share the same hardware).
       if isolation fails then one customer can access anothers data including 
        memory isolattion failure , vm escape , guest hopping 

  4. compliance risks : company needs to follow rules like GDPR,PCI DSS , ISO 
      if the clodu provider cannot prove compliance or doesnt allow audits -> you may loose your certification 
      ex: if bank moves to clodu and clodu provider doesnt meet PCI DSS -> Bank becomes non-compliant → huge legal issues.
  5. Management interface compromise : clodu control panels are accessible via the internet.
      If an attacker hacks: admin portal , api keys they can control everything. 
      ex: he  can delete servers, steal data, shut down services 
  6. data protection risks : 
      You (customer) cannot always check how the provider handles:
       storage, backups , encryption , admin access 
       So you may not know if the data is handled legally or securely.

  7. INSECURE OR INCOMPLETE DATA DELETION
      in cloud data exists in multiple copiees, sored across multiple disks 
       even if you delte some copies remain and delted may still be recoverable 
  8. MALICIOUS INSIDER :
      Someone inside the cloud provider (admin, security staff) may misuse their privileged access.
      ex: A cloud admin with access to physical servers could steal or leak data of thousands of customers.
       these are rare but so dangerous 

    | **Risk**                            | **Meaning (Short & Clear)**                                                           |

     If they can’t → you lose compliance too.

//multi-tenant 
   Many customers (tenants) share the same cloud hardware:
    Same server
    Same storage pool
    Same hypervisor

BUT their workloads must remain fully isolated.

Securing Multi-Tenant Environments :
  1. No tenant can communicate with another tenant’s VMs - No access to other customer’s networks
  2. Even privileged users must not break isolation - admin should not modify anything this prevents insider threats 
  3. Every admin action must be logged per tenant - For audit, compliance, and forensics.


In multi-tenant cloud, everyone shares hardware 
 — so the cloud provider must isolate each tenant’s VMs, networks, 
 and admins, and track all actions to prevent cross-access.

    Audit → checking if rules were followed
    Compliance → proving you follow laws/standards
    Forensics → investigating what went wrong

 security in multi-tenant cloud 
 1. cloud protection -
        - Even cloud admins can’t misuse access.
        -  Every admin action is logged and controlled.
 2. Data Encryption (Protect Data at Rest)
    encrypts fiels, vms, workloads and also manages the encryption keys 
   Even if someone steals the storage, they cannot read the data.
 3. Key Management (Hardest Part of Encryption) :
   managing all keys -> by central key management , key rotation, keys dont get lost , leaked or mismanaged 



//vulnerability 
  it is a weakness which can be exploited by an attacker to perform unauthorized actions within a computer system.
  1. system flaw 
  2. attacker access to flaw 
  3. attacker exploit the flaw 
  for exploiting he needs vulnerability scanning tools 
   nesus, nikto2 ,netparker 

1. vulnerabilities in virtual machines (vms)
  . covert channels -> Two VMs side-by-side can leak info to each other.
  . Unrestricted allocation & deallocation -> VM deleted → memory wasn’t cleaned → attacker gets leftover data.
  . Uncontrolled Migration -> VM moves from Server A → Server B → attacker sniffs the migration.
  . Uncontrolled Snapshots(vm state) -> Snapshot contains passwords → attacker steals snapshot → reads data.
  . Uncontrolled Rollback -> VM patched → snapshot taken → rollback → patch lost → security hole reappears.
  . Visible VM IP addresses -> Attackers can map the cloud infrastructure (cloud cartography) and target specific VMs.

2. Vulnerabilities in Virtual Machine Images (VMIs)
  . Uncontrolled placement -> VM images stored in public repos can be downloaded by attackers.
  . VM images cannot be patched -> images are templates , They don’t update themselves automatically.

3. Vulnerabilities in Virtual Networks
  .  Internet-based protocols -> Cloud uses normal internet protocols (HTTP, TCP/IP), which are vulnerable to attacks 
  . Sharing virtual bridges -> Multiple VMs share the same virtual network components (like virtual switches). if misconfigured they attackers attack 

| Category             | Vulnerability (Easy Meaning)                                                   |
| -------------------- | ------------------------------------------------------------------------------ |
| **VMs**              | Secret channels, bad migration, unsafe snapshots, rollback risk, IP visibility |
| **VM Images**        | Public repo exposure, outdated/unpatchable templates                           |
| **Virtual Networks** | Internet threats (MITM), shared network components                             |


//Hypervisor 
 A hypervisor is the software that allows multiple VMs to run on one physical machine
  If the hypervisor gets hacked → ALL VMs running on it are at risk.
  ex: xen , vmware 

//vulnerabilites of hypervisor 
 so actually vm is it its own environemnt 
 1. guest-to host escape -> vm breaks out of its jail 
    The attacker inside one VM jumps into the host hypervisor and starts running code there.
    Once they hack the host →
    They can control EVERY VM on that machine.
 2. VM Hopping done in two steps 
   step1 : attacker hacks one vm (usign weak password or unpatched os)
   step2 : They exploit a hypervisor vulnerability and jump (“hop”) from this VM to another VM on the same physical machine.
      Like moving from VM1 → VM2 → VM3.

 | Attack                   | What Happens?                                                          |
| ------------------------ | ---------------------------------------------------------------------- |
| **Guest-to-Host Escape** | Attacker breaks out of VM → controls the hypervisor → controls all VMs |
| **VM Hopping**           | Attacker breaks out of VM → goes directly to another VM                |

 2. ARP Spoofing 
    ARP (Address Resolution Protocol) maps: IP Address → MAC Address
    ARP trusts all replies without verification.
    There is no authentication.
    ARP Spoofing =
    When an attacker sends fake ARP replies to trick a victim into mapping:
    Router IP → Attacker MAC

    Now all victim traffic goes to the attacker instead of the router.
    Once the victim sends all traffic to the attacker instead of the router, the attacker becomes a silent middleman.
    1. Man-in-the-Middle (MITM)
      Attacker sits between victim and internet:
       Victim → Attacker → Router → Website
       Website → Router → Attacker → Victim
    The victim has no idea this is happening.
    2. Steal Sensitive Data
    he can steal passwords,logins, emails , cookies , otps 
    3. modify the data : Attacker can change what the victim sees or sends.
    4. Replay Attacks -> Attacker can resend a previously captured request to perform:
       Fake transactions, fake loginsm unauthorized actions 
    5. Drop Packets (DoS Attack) -> Attacker can simply not forward the victim’s traffic to the router.
                  -> internet stops, website doesnt load, services fail 

3. Man in the middle attack

4. IP Spoofing 
     Attacker changes (forges) the source IP address in a packet so it looks like the packet came from someone else.
     The attacker pretends to be another IP address.

     why do they do 
     1. hide their identity 
     2. impersonate a trusted device 
     3. bypass firewalls 
     4. perform attacks like dos,ddos, mitm 
    
    how ip spoofing works 
    1. attacker creates a packet 
    2. they cahnge the source ip address to someone else ip 
    3. packet is sent to the victim 
    4. victim thinks it came from spoofed ip 
    
    IP spoofing works mostly in connectionless protocols like UDP.
    It is much harder in TCP because TCP needs a 3-way handshake.

//TCP Handshaking in IP Spoofing
  TCP uses a 3-way handshake to start a connection:
     1. Client → SYN
    2. Server → SYN-ACK
    3. Client → ACK
   Only after these 3 steps, communication begins.

 Why does handshake matter for spoofing?
   so servers syn-ack is sent to the fake ip (attackers) 

   Attacker writes fake IP → server replies to fake IP → attacker never receives reply → handshake fails → TCP spoofing becomes hard.

5. DNS Spoofing 
  DNS = Domain Name System
   It translates website names into IP addresses.
   ex: www.google.com → 142.250.xx.xx

  In DNS spoofing, the attacker poisons or changes the DNS reply so that:
   When client asks for real website, DNS gives IP of a fake website.

   now he can steal user entered name,password -> attacker steals it 

   DNS Spoofing is an attack where the attacker corrupts DNS responses so that a domain name resolves to a fake, malicious IP address instead of the real one.

6. DDos attack (Distributed Denial of Service)

  DoS = Denial of Service 
      Attacker sends lots of traffic to a server → server becomes overloaded → stops serving legitimate users.
      But this is done using one machine only. this is Dos 
  DDoS = Distributed Denial of Service
      Instead of one attacker, there are hundreds or thousands of machines attacking at the same time.

      these machines form botnet -> network of infected , controlled by bobmaster 

DDoS is an attack where multiple compromised systems flood a server with traffic, overwhelming it and making it unavailable to legitimate users.
